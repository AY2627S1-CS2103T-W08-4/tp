## Findings

### A01 — Logging failure prevents application startup (provisional Medium)

- Confirmed in a fresh Java process against baseline packaged main classes.
- Start in a disposable folder containing a directory named `addressbook.log.0`.
  This forces FileHandler creation to fail; an unwritable log location has the
  same error path.
- Expected: log a warning to the already-installed console handler and continue.
- Actual: `ExceptionInInitializerError`, caused by NullPointerException at
  `LogsCenter.setBaseLogger`, because the static `logger` field is assigned only
  after that method returns. Main initializes logging before opening the app.
- Minimal fix candidate: report through the initialized `baseLogger`. Test in
  separate processes because the failed class initialization poisons that JVM.
- No corresponding open issue was present when issues were read. Local finding;
  no remote issue/PR created.
